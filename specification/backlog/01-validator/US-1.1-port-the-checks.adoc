=== US-1.1 Port the checks of the Python validator

Status:: Done (0.1.0) +
Effort:: 4 h +
Traces to:: <<TS-1.1>>, <<TS-1.3>>, <<FR-1.1>>, <<FR-1.2>>, <<FR-1.3>>, <<FR-1.4>>, <<FR-1.6>>, <<NFR-1>>

As a developer of a project in any language, I want the specification checks as one binary,
so that I do not need Python to validate my specification.

.Acceptance criteria
. Every check of FR-1.1 to FR-1.4 reports with the message of the Python validator.
. Exit codes and output follow FR-1.6.
. On the wos-intel specification, valid and with injected faults, the Go and Python
  validators report the same problems.

.Test criteria
* Unit test (`internal/spec`): one generated tree per rule in `t.TempDir()`, ported from
  `tests/test_validate_specs.py` of wos-intel, plus CRLF input.
* Component test (`cmd/spec-validator`): `run` with valid and faulty projects, every usage
  error, `-version`.
* Integration test: this repository's own specification validates (`TestOwnSpecification`).
* Parity: manual comparison against the Python validator on wos-intel (done for 0.1.0).
