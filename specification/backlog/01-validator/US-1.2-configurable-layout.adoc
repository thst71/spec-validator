=== US-1.2 Configurable layout

Status:: Done (0.1.0) +
Effort:: 2 h +
Traces to:: <<TS-1.2>>, <<TS-1.3>>, <<FR-1.5>>

As a developer of a project with its own specification layout, I want to configure masters,
folders, kinds and traceability, so that the validator fits my project.

.Acceptance criteria
. `.spec-validator.json` in the root or `-config <file>` replaces the default layout.
. Every configuration error of FR-1.5 ends the run with exit code 2 and a message naming the
  file.

.Test criteria
* Unit test: a custom layout with its own kinds and rule; one case per configuration error;
  the default configuration passes its own check.
* Component test: explicit `-config`, broken and missing configuration files.
