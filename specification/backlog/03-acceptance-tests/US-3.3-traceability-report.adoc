[[US-3.3]]
=== US-3.3 Traceability report

Status:: Done (0.2.0) +
Effort:: 3 h +
Traces to:: <<TS-3.4>>, <<TS-3.5>>, <<FR-3.5>>

As the owner of a product, I want every release to show which requirements its acceptance
tests cover, so that orphaned tests and uncovered requirements are visible.

.Acceptance criteria
. `-trace-report` writes `traceability-report.adoc` with the four sections and the summary of
  FR-3.5; `-results` adds the results.
. Empty sections say "none"; the exit code is 0 with orphaned scenarios or uncovered
  requirements.
. Without a test report master, scenario IDs are plain text; with it, references.

.Technical tasks
. `trace.go`.
. The `-trace-report` and `-results` flags.
. Tests below.

.Test criteria
* Unit test: coverage maps from a fixture: covered, uncovered, orphaned, a scenario tracing to
  two requirements, a requirement covered twice.
* Component test: `run -trace-report` with and without `-results`, `-results` without
  `-trace-report` (exit 2).
* Integration test: golden file (`testdata/traceability-report.adoc`); rendering in the render
  chain test of <<US-3.4>>.
* Blackbox test: none; see <<US-3.1>>.
