[[TS-2.1]]
=== TS-2.1 Build and release

Implements <<FR-2.1>>, <<NFR-1>> and <<NFR-2>>.

* `Taskfile.yml` maps the agent-skills task contract: `typecheck` = `go build ./...`, `lint` =
  `golangci-lint run`, `format-check` = `gofmt -l`, `test` = `go test -race -cover ./...` run by
  `gotestsum`, which writes the time of every test to `build/test/junit.xml`, `validate-specs` = `go run ./cmd/spec-validator` (from source: the launcher would run a
  pinned release of this very tool), `check` = all of them.
* `.github/workflows/ci.yml`: the gate on ubuntu and macos, `go test ./...` on windows.
* `.github/workflows/release.yml`: the agent-skills release template with the go-task Release
  Build. `verify`, `docs` (render-docs with `validator: go run ./cmd/spec-validator`) and
  `publish` use release-actions, pinned by commit SHA. GoReleaser v2 (`.goreleaser.yaml`) only
  builds: `-trimpath`, `CGO_ENABLED=0`, `-X main.version`, archives with the license files;
  its own checksums and changelog are disabled.
* The release interface of <<FR-2.1>> comes from `.goreleaser.yaml` (`name_template`
  `{{ .ProjectName }}_{{ .Version }}_{{ .Os }}_{{ .Arch }}`, the binary at the root) and
  publish-release (`checksums.txt`); `-version` prints `main.version`, set to the version
  without `v`, or the module version (`v<version>`) for `go install`.
* The agent-skills library is vendored into `.agents/skills/` with its `vendor.sh`. A release
  changes neither the library nor the projects: each project pins a release in its
  `.agents/spec-validator.lock` and raises it with the launcher's `--update`.
